# Scripted tool and resource QA with browser previews — November 18, 2026

This was the first run of the [live browser runbook](../../live-browser-qa.md) in its scripted form. `scripts/qa_live.py` ran against project 14356 (PolicyChecks), Silver, and the maintainer then opened each generated proposal URL in a signed-in browser and compared the edit form with the report. No Save or Submit action was performed.

The server was bestpractices-mcp 0.5.0 run from the source checkout at commit `f1c2ce8`, on protocol 2026-07-28, under macOS 15.8.3. This was a development check of the script and runbook. It does not qualify a release, because the server was not an installed candidate.

The reset previews repeat the 2026-11-16 observation recorded in [ADR 0005](../../adr/0005-proposal-intent-and-compatibility-warnings.md#context-and-observations), on different criteria: a proposal of `?` did not replace a saved status with or without a saved justification, with named overrides, with the wildcard, or with none, while an ordinary override of the same controls applied.

The maintainer noted one result outside the runbook's expectations: `achieve_passing` is a disabled control on the Silver edit form, yet the control proposal changed its displayed status to `Unmet`. A proposal URL with an override can therefore change a status in the preview that a person cannot change by hand. Nothing was saved, so this run does not show whether BadgeApp would keep such a value. The retained upstream sources do not describe how this control is managed.

After the control preview the plain edit page was reopened, and the maintainer confirmed that the restored form matched the baseline. A `get_project_answers` read also returned all 66 Silver status and justification fields unchanged from the read taken before the previews.

## Limits

- Every URL was delivered with the macOS `open` command to the default browser. The runbook's two delivery routes, clicking the rendered link and pasting the raw URL into the address bar, were not exercised.
- No screenshots were taken. The script's `report.md` and `calls.json` are kept locally under ignored `INTERNAL/` and are not committed.
- In the chooser case the Baseline Level 1 field proposed `Met` for a criterion already saved as `Met`, so that section could show forwarding of the query but no changed control.
- The script chose `achieve_passing` because it was the only Silver criterion with a saved status and no justification. It does not know that the form disables this control, so the reset result for it may not represent an ordinary criterion.
- The optional host and repository-file cases were not run.
